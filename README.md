# IPv4 VLSM 地址规划台

本地运行的 IPv4 可变长子网掩码（VLSM）地址规划工具。基于 **React 18 + TypeScript + Vite**，纯前端计算，数据不离开本机。

## 功能

- **录入父 CIDR**（如 `192.168.10.0/24`）。
- **保留区**：以 CIDR 形式录入，不参与需求分配。
- **需求列表**：每项填写「主机数」和**可选**的固定网段（CIDR）。
- **自动网段容量**：按「可用主机数 = 地址数 − 2」（扣除网络地址与广播地址）取最小 2 的幂分块，**最小为 /30**（4 个地址、2 个可用主机）。
- **校验规则**：
  - 保留区和固定网段必须完全位于父网段内；
  - 保留区与固定网段之间、以及彼此之间**互不重叠**；
  - 固定网段的可用主机数必须足够容纳该需求，否则报错并给出实际可用数。
- **分配算法**：自动需求按规模**从大到小**排序，同规模按**录入顺序**，在保留区/固定网段/已分配网段之外选取**最低的、满足前缀边界对齐**的空闲块；放不下时在页面上说明原因（最大连续空闲块大小 / 对齐不满足）。
- **比例地址条**：按地址数比例区分 🟠 保留、🟣 固定、🟢 自动、⚫ 空闲四类区域。
- **点击交互**：点击地址条色块或明细表任意行，展示该项的**网络地址、广播地址、可用范围、容量与浪费量**。
- **基线对比**：把当前无输入错误的规划保存为基线，修改后按需求的稳定 ID 比较新旧结果。
- **路由汇总**：勾选当前成功分配的固定 / 自动网段，将所选地址并集汇总为**数量最少且覆盖精确**的 CIDR 列表，逐条展示地址数与覆盖的原需求，支持一键复制按网络地址升序排列的纯 CIDR 列表。
- **导出 JSON**：一键导出包含父网段、统计、全量网段明细及失败原因的 JSON 文件（时间戳命名）。

## 快速开始（Docker Compose，一条命令）

```bash
docker compose up -d --build
```

启动后浏览器访问：

> **http://localhost:8080**

停止：

```bash
docker compose down
```

> 端口占用时修改 `docker-compose.yml` 中的 `"8080:80"`，例如改为 `"9090:80"`。

## 使用示例

点击页面上的「**载入示例**」可快速体验，示例等价于：

| 名称 | 主机数 | 固定网段 | 类型 / 规划结果 |
| --- | --- | --- | --- |
| 核心交换链路保留 | — | `192.168.10.0/28` | 保留（0–15） |
| 办公区 VLAN | 100 | | 自动（128/25，126 可用） |
| 机房 VLAN | 40 | | 自动（64/26，62 可用） |
| 监控固定段 | 25 | `192.168.10.32/27` | 固定（32–63，30 可用） |
| 设备管理 | 2 | | 自动（16/30，2 可用） |

自动需求按规模从大到小处理：`/25` 在最低对齐地址 128 落位（16–31 的间隙放不下）；`/26` 落到 64；`/30` 最后填入最低空闲间隙 16。最终保留 16 + 固定 32 + 自动 196 = 244 个地址，剩余 12 个空闲（20–31、192–255），利用率 95.31%，浪费 53 个地址。

## 基线对比（按稳定 ID）

页面 **④ 基线对比** 面板提供「保存 → 修改 → 对比」工作流：

1. **保存基线**：当前规划没有输入错误时，点击「保存当前规划为基线」。基线包含父网段、每个需求（成功分配的网段与失败原因）和全部占用地址区间。
2. **修改输入**：调整父 CIDR、保留区或需求。每条需求在添加时获得一个**稳定 ID**，改名、改主机数或换固定网段都保持同一 ID，因此对比不依赖名称。
3. **查看对比**：面板与「网段明细」表实时刷新，每个需求归入下列状态之一：

   | 状态 | 含义 |
   | --- | --- |
   | 🟢 新增 | 基线保存后新添加的需求 |
   | 🔴 删除 | 基线中存在、当前列表已删除的需求 |
   | ⚪ 未变 | 网段 CIDR 与容量均未变 |
   | 🟡 扩容 / 缩容 | 容量变化（CIDR 改变时同时标记迁移） |
   | 🔵 迁移 | 网段 CIDR 改变即视为迁移；容量同时变化时叠加「扩容/缩容」标记 |
   | 🔴 未分配 | 基线时已分配、当前因空间不足等原因分配失败 |
   | 🟢 恢复分配 | 基线时分配失败、当前已成功分配 |
   | ⚪ 仍未分配 | 两个时点都分配失败（附当前失败原因） |

4. **地址区间汇总**：按地址区间列出
   - **新占用**（基线空闲 → 当前占用）、**释放**（基线占用 → 当前空闲）、**仍占用**（两个时点都占用）；
   - 区间自动合并去重，重叠地址**不重复计数**，满足「新占用 + 仍占用 = 当前占用」「释放 + 仍占用 = 基线占用」；
   - **净地址变化 = 新占用 − 释放**（正数表示占用增加）；
   - 变化地址条用 🟩 新占用 / 🟥 释放 / ▫️ 仍占用 三色按比例展示，悬停可看具体区间。
5. **清除 / 重建**：「清除基线」立即移除（同时删除会话存储）；「重建基线」用当前规划覆盖旧基线。
6. **输入非法时**：基线予以保留，面板显示暂停提示并停止对比；输入修正后自动恢复，无需重新保存。

> 基线仅保存在**当前浏览器会话**（`sessionStorage`）：刷新页面仍在，关闭标签页或浏览器后自动消失；不上传任何服务器。

## 路由汇总

页面 **⑤ 路由汇总** 面板用于把多条已规划网段汇总成便于下发路由（如静态路由 / OSPF 汇总）的精简 CIDR 列表：

1. **勾选网段**：列表只包含当前**成功分配**的固定、自动网段（带类型徽标与各自 CIDR）。可单选、多选或「全选 / 全不选」。
2. **汇总算法**：先把勾选网段的地址区间**合并相邻区间**，再对每个连续区间**按地址对齐边界贪心拆分**为 CIDR（每一步取起点可对齐的最大 2 的幂块）。因此：
   - 结果 **CIDR 数量最少**，并集与所选地址**严格相等**（不多一个、不少一个）；
   - **只有同前缀、连续且同属一个上级网段**的两个块才会被聚合（例如同属一个 `/29` 的两个 `/30` 聚合成 `/29`；`4/30` 与 `8/30` 虽连续但上级 `/29` 不同，则不聚合）；
   - 任何汇总项都**不包含未选需求、保留区或空闲地址**（区间不相邻就绝不跨越）。
3. **结果展示**：逐行列出汇总 CIDR、地址数以及它覆盖的**原始需求名称与网段**；由多段聚合而成的行带「聚合」标记；顶部给出「已选网段数 / 地址总数 → CIDR 数」。
4. **一键复制**：点击「📋 复制 CIDR 列表」复制**按网络地址升序**排列的纯 CIDR（每行一个），适合直接粘贴进路由配置；复制成功有「✓ 已复制」反馈。
5. **禁用与自动清理**：输入非法或没有成功分配的网段时整个面板禁用并提示原因；规划变化后，已删除或分配失败的网段会自动从勾选中移除（同一需求 ID 重新成功分配时其勾选保留）。

> 汇总只读取当前规划结果，全部在浏览器本地完成。

## 分配规则说明

1. 需求主机数 `h` → 网段大小取满足 `size − 2 ≥ h` 的最小 2 的幂，`size ≥ 4`，即前缀 `≤ /30`。
2. 先登记保留区和固定网段（校验包含性、互不重叠、固定段容量足够）。
3. 自动需求按所需前缀从小到大（规模大→小）排序；所需前缀相同时保留录入顺序。
4. 对每个需求，按地址升序扫描空闲间隙，取第一个能容纳该块、且起始地址对齐到其前缀边界的间隙；这就是「占用区之外的最低对齐空闲地址」。
5. 若所有间隙都无法容纳，报告：当前最大连续空闲块、所需块大小与前缀，或边界对齐不满足的原因；其余需求继续尝试分配（互不影响）。
6. 浪费量 = 自动/固定网段的（可用主机数 − 需求主机数）；保留区与空闲区不计入浪费统计。

## 基线对比规则说明

1. 每条需求在新增时生成稳定 ID，随输入编辑保持不变；对比按 ID 匹配，重命名不影响匹配。
2. 状态判定：同一 ID 的两个时点都是已分配时，CIDR 相同 → 未变（或纯容量变化）；CIDR 不同 → 迁移，并在容量同时变化时叠加扩容/缩容。已分配 ↔ 失败分别记为未分配 / 恢复分配；两侧均失败记为仍未分配。
3. 地址区间对比基于「保留 + 固定 + 自动」的占用集合：`仍占用 = 基线 ∩ 当前`，`新占用 = 当前 − 基线`，`释放 = 基线 − 当前`；区间经扫描线合并，重叠地址只计一次。
4. 净地址变化 = 新占用地址数 − 释放地址数，与「当前占用总量 − 基线占用总量」相等（同一父网段时）。
5. 基线仅允许在无输入错误时保存/重建；存在输入错误时保留基线、暂停对比；基线存于 `sessionStorage`，关闭浏览器即清除。

## 路由汇总规则说明

1. 勾选集合取当前规划中成功分配的固定 / 自动网段（均为彼此不重叠、且已对齐 CIDR 边界的网段）。
2. 将所选区间排序后，仅在**端点相接**（相邻）时合并；中间隔着任何未选地址（未选需求、保留区、空闲）都不会合并。
3. 对每个合并后的连续整数区间做最少 CIDR 拆分：从游标起取「起点能对齐、且不超过区间剩余长度」的最大 2 的幂块，逐块推进。该贪心得到的块数最少（区间到 CIDR 的经典分解）。
4. 聚合因此是安全且精确的：两个块被合并，当且仅当它们前缀相同、地址连续且同属一个上级网段（例如 `0/30` 与 `4/30` 合为 `0/29`）；跨上级边界（如 `4/30` 与 `8/30`）会在边界处拆成两个块。
5. 每个汇总块回查覆盖到的原网段，逐行展示其名称与 CIDR；汇总总地址数恒等于所选网段容量之和（无重复、无遗漏）。
6. 复制输出按网络地址升序、每行一个 CIDR；输入非法或没有成功分配网段时面板禁用；规划变化后自动剔除已不存在或分配失败的勾选。
